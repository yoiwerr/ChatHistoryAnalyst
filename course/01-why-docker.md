# 第一课：为什么要用 Docker

## 一个真实的故事

你写了一个 Python 项目，在自己电脑上跑得完美。然后你买了一台云服务器，把代码传上去，运行——报错。

一看日志：`ModuleNotFoundError: No module named 'fastapi'`。哦，忘了装依赖。

装好依赖，再跑——又报错：`pg_config not found`。哦，服务器上没装 PostgreSQL 开发库。

装好 PostgreSQL，再跑——还报错：Python 版本是 3.10，但你用到了 3.12 的语法。

你开始怀疑人生：**为什么在我电脑上能跑，服务器上就不行？**

这个问题的本质是：**你的电脑和服务器环境不一致**。

Docker 解决的就是这个问题。

---

## 环境不一致的根源

让我们拆解一下"环境"到底包括什么：

```
你的项目要跑起来，依赖这些层：

┌──────────────────────────────┐
│         你的 Python 代码      │  ← 这个是可控的（你写的）
├──────────────────────────────┤
│     pip 包 (fastapi, etc)    │  ← 这些东西的版本在不同机器上可能不同
├──────────────────────────────┤
│   系统库 (libpq, openssl)    │  ← 服务器上可能根本没装
├──────────────────────────────┤
│    Python 解释器 (3.12)      │  ← 服务器上的 Python 可能是 3.10
├──────────────────────────────┤
│      操作系统 (Ubuntu)       │  ← 你用的是 24.04，服务器是 22.04
└──────────────────────────────┘
```

传统做法是：每次部署，手动把这些层都对齐。你在 TODO.md 里就看到了这个痛苦的过程——安装 Docker 本身只是第一步，装完后还要装各种东西。

Docker 的做法是：**把这整个栈打包成一个文件，服务器直接运行这个文件**。

---

## Docker 是什么（用外卖类比）

假设你开了一家餐厅：

| 现实世界 | Docker 世界 |
|----------|------------|
| 你写了一份菜谱 | `Dockerfile`（镜像构建指令） |
| 把菜谱交给中央厨房，做成一个真空料理包 | `docker build` → 生成一个 **Image（镜像）** |
| 料理包送到分店，拆开加热就能卖 | `docker run` → Image 启动成一个 **Container（容器）** |
| 同一份料理包，全部分店味道一模一样 | 同一个 Image 启动的 Container，环境完全一致 |
| 料理包存放在冷库，随用随取 | Image 存放在 **Registry（镜像仓库）**，Docker Hub 是最大的公共冷库 |

关键区别：
- **Image（镜像）**：静止的，就像一个 `.iso` 光盘映像文件
- **Container（容器）**：运行的，就像你用那个 `.iso` 启动的虚拟机

---

## 我们这个项目为什么需要 Docker

看 `docker-compose.yml`，我们实际上要启动 **四个** 服务：

| 服务 | 作用 | 需要什么环境 |
|------|------|------------|
| PostgreSQL + pgvector | 向量数据库 | pgvector 扩展、特定的 PG 版本 |
| FastAPI | 后端 API | Python 3.12、一堆 pip 包、libpq-dev |
| Streamlit | 前端页面 | Python 3.12、另一堆 pip 包 |
| Nginx | 反向代理 | 不需要 Python，但需要特定的 Nginx 配置 |

如果不用 Docker，在服务器上手动配这四个——光是让 pgvector 扩展在正确版本的 PostgreSQL 上跑起来，就够折腾 2 小时。而且每次换服务器都要重新折腾。

用 Docker 之后：**一台新服务器，装好 Docker → 一条命令 → 四个服务全部就绪**。

这就是 `/scripts/deploy.sh` 最后做的事：它只调用 `docker compose up -d`，四个服务就都起来了。

## Docker vs 虚拟机

很多人问：Docker 是不是和 VMware 一样的虚拟机？

**不是，完全不是。**

```
虚拟机 (VMware/VirtualBox):
┌─────────────────────────┐
│      你的 Python 代码    │
├─────────────────────────┤
│      Guest OS (Ubuntu)  │  ← 完整的操作系统内核，占 2GB+
├─────────────────────────┤
│   Hypervisor (VMware)   │
├─────────────────────────┤
│     Host OS (你的系统)   │
├─────────────────────────┤
│       物理硬件           │
└─────────────────────────┘

Docker 容器:
┌─────────────────────────┐
│      你的 Python 代码    │
├─────────────────────────┤
│     Docker Engine       │  ← 不是完整 OS，只隔一层，占几十 MB
├─────────────────────────┤
│     Host OS (你的系统)   │
├─────────────────────────┤
│       物理硬件           │
└─────────────────────────┘
```

Docker **共享宿主机的操作系统内核**，不虚拟一套完整的 OS。所以：
- Docker 容器启动只需 **秒级**（虚拟机要分钟级）
- Docker 容器吃 **几十 MB** 内存（虚拟机要 GB 级）
- Docker 容器文件大小通常 **几百 MB**（虚拟机镜像通常几 GB）

## 本课小结

| 你学到的 | 一句话解释 |
|----------|-----------|
| Docker 解决什么问题 | "在我机器上能跑" → 在任何机器上都能跑 |
| Image vs Container | Image 是料理包（静止），Container 是热菜（运行中） |
| Docker vs VM | Docker 共享内核、轻量；VM 虚拟完整 OS、笨重 |
| 我们项目为什么用 Docker | 四个服务（PG/FastAPI/Streamlit/Nginx），一条命令全启动 |
